# Javadoc Fixer Maven Plugin - Usage Guide

## 🚀 Installation & First Build

### 1. Build the Plugin

Before using the plugin, you must compile and install it in your local Maven repository:

```bash
# From the project root
mvn clean install -pl javadoc-fixer-maven-plugin -DskipTests
```

### 2. Verify Installation

```bash
mvn help:describe -Dplugin=com.weedow:javadoc-fixer-maven-plugin:{version}
```

## 📋 Usage Overview

This plugin is designed to fix missing or incomplete Javadoc in source files generated by Lombok's `delombok` goal. Specifically, it fixes:
- Empty default constructors without Javadoc.
- The `canEqual(Object other)` method generated by Lombok.

### Testing on the `commons` Module

```bash
# Clean and generate sources using the release profile
mvn clean generate-sources -pl commons -P release

# Verify that the delomboked files have been fixed
cat commons/target/delombok/com/weedow/schemaorg/commons/model/SchemaDataType.java
```

## 🔍 Verification

### Before the Fix (Constructors)

```java
@java.lang.SuppressWarnings("all")
@lombok.Generated
public MyClass() {
}
```

### After the Fix

```java
/** Default constructor */
@java.lang.SuppressWarnings("all")
@lombok.Generated
public MyClass() {
}
```

### Before the Fix (canEqual)

```java
@java.lang.SuppressWarnings("all")
@lombok.Generated
protected boolean canEqual(final java.lang.Object other) {
    return other instanceof MyClass;
}
```

### After the Fix

```java
/**
 * canEqual method.
 * @param other Other.
 * @return true or false
 */
@java.lang.SuppressWarnings("all")
@lombok.Generated
protected boolean canEqual(final java.lang.Object other) {
    return other instanceof MyClass;
}
```

## ⚙️ Advanced Configuration

### Temporarily Disabling the Plugin

```bash
mvn clean install -P release -Djavadoc.fixer.skip=true
```

### Configuring the Plugin in `pom.xml`

By default, the plugin looks in `${project.build.directory}/delombok`. If your delombok output directory is different, configure it in your `pom.xml`:

```xml
<plugin>
    <groupId>com.weedow</groupId>
    <artifactId>javadoc-fixer-maven-plugin</artifactId>
    <version>${project.version}</version>
    <configuration>
        <sourceDirectory>${project.build.directory}/custom-delombok</sourceDirectory>
    </configuration>
    <executions>
        <execution>
            <id>fix-javadoc</id>
            <phase>generate-sources</phase>
            <goals>
                <goal>fix-javadoc</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

## � Troubleshooting

### Plugin Cannot Find Files

**Error:** `Source directory does not exist: /path/to/delombok`

**Solution:** Ensure that the `lombok-maven-plugin` executes **before** the `javadoc-fixer-maven-plugin`. The order of declaration in the `pom.xml` matters:

```xml
<!-- MUST be declared first -->
<plugin>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok-maven-plugin</artifactId>
    <!-- ... -->
</plugin>

<!-- Extends delombok outputs -->
<plugin>
    <groupId>com.weedow</groupId>
    <artifactId>javadoc-fixer-maven-plugin</artifactId>
    <!-- ... -->
</plugin>
```

### Fixes Are Not Applied

**Problem:** The Java files in the target directory are not modified.

**Solutions:**
1. Ensure the generated methods have the `@java.lang.SuppressWarnings("all")` and `@lombok.Generated` annotations exactly as generated by Lombok.
2. Enable debug logging with `-X` (`mvn clean generate-sources -P release -X`) to see details on which files were processed.
